# 日语敲敲：云同步配置

## 1. Supabase

项目地址：`https://impjceezjrvmgqpwuttu.supabase.co`。

1. 在 SQL Editor 中按文件名顺序运行 `supabase/migrations/` 下的全部脚本；已部署的项目只需运行尚未执行的脚本（目前是 `202610120001_resilient_sync.sql` 和 `202610120002_learning_records_only.sql`）。脚本在事务内创建专用表和 RPC，不修改现有业务表；后者会删除云端已有的卡组和设置副本（见下文）。新迁移执行前，网页会自动退回旧的整批上传接口，所以先部署网页或先执行迁移都可以。
2. Authentication → Providers 中启用 Email，并保留确认邮箱；将最低密码长度设为 6，不要求大小写、数字或符号组合。前端也采用 6 个字符；已有项目需在控制台更新，公开 API key 无法修改此设置。
3. Authentication → URL Configuration：Site URL 设置为 `https://wjin999.github.io/qiaoqiao/`；Redirect URLs 加入同一地址，开发时另加 `http://localhost:5173/` 和 `http://127.0.0.1:5173/`。更换域名前先添加新地址，完成旧站记录同步或备份后再跳转。
4. API Keys 中复制 Publishable key（或旧版 anon PUBLIC key）。**不使用 Secret key、service_role、数据库密码。**
5. 把 `.env.example` 复制为 `.env.local`，填写公开 key。重启开发服务器。
6. GitHub 仓库 Settings → Secrets and variables → Actions → Variables 中添加 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_PUBLISHABLE_KEY`。这些是公开浏览器配置，不是管理员凭据。再添加 `ACCOUNT_SYNC`，值为 `true`；没有这个变量时，部署不带公开 key，线上版本只作为本地练习工具（目前即是如此）。重新运行部署 workflow 后生效。

## 2. 邮箱与公开注册

Supabase 默认发信仅适合项目团队测试，不能据此认为普通用户能注册。公开注册前配置 Custom SMTP，使用已验证的发信域名；验证 QQ、163、Gmail 等真实邮箱能收到验证和重设密码邮件。免费发信额度、项目休眠与容量上限以提供商控制台为准。

密码和会话由 Supabase Auth 管理，本项目数据库不保存明文密码。网页使用 HTTPS。默认 API key 是公开的，权限由服务器验证的用户身份决定。

## 3. 同步行为与容量

陪练伙伴功能已移除：旧版本写入的 `qiaoqiao.companion.v1` 设置和逐句记录中的 `petId` 仍被服务器和网页接受，但网页不再读取或写入它们。

- 游客保留原来的 IndexedDB 和 localStorage 标识，改名不迁移或清除旧记录。登录后使用独立账号数据库，用户可以主动合并游客记录；原游客数据不删除。
- 只同步学习记录：逐句评分、练习历史、复习计划检查点和永久跳过，即进度备份里的内容。卡组随网站发布、在本机加载，不保存在云端；练习设置（学习语言、练习方式、每日新句上限、练习范围）也只保存在本机，换设备需重新设置。`202610120002_learning_records_only.sql` 删除云端已有的卡组和设置副本；未刷新的旧页面仍上传它们时，服务器返回成功但不保存，旧页面的队列因此能清空。
- 本地写入和待同步队列使用同一 IndexedDB 事务；游客不建立上传队列。变化分批上传，服务器逐条返回结果：接受的记录出队；暂时不能接受的（设备时间快于服务器、云端容量已满）留在队列下次重试；永远无法存储的（如超过 16 KiB 的单条记录）移出队列、只保留在本机，不再阻塞其他记录。页头状态会注明这些情况。
- 上传失败时仍会下载其他设备的记录。下载使用服务器版本游标；本版本读不懂的云端记录（例如更新版本写入的）先隔离保存，不阻塞同步，网页更新后自动补读。下载时只重算受影响句子的复习计划。
- 重复请求通过 mutation ID 去重，去重凭据在服务器保存 30 天：已成功上传但本机未确认、又离线超过 30 天的设备，重新上传的旧跳过状态可能覆盖其他设备期间的修改。同步是单向请求拉取，不建立长期实时连接。
- 登录用户完成一组记忆复习或自由跟打后，在最后一条记录保存成功、进入结算页时自动同步一次学习记录。逐句输入、未完成就返回主页、登录、重新联网、切回页面不会自动触发。仍保留页头「同步」和账号窗口「立即同步」。离线或失败时保留本地队列并提示手动重试，不循环重试；下一组完成会再次尝试。同步中暂停开始下一组，防止练习时应用云端变化。换设备前确认已同步，再在新设备登录并同步。
- 评分日志不可覆盖；所有设备使用固定版本的 FSRS 重放同一句的评分，时间相同按事件 ID 排序。缺少完整日志的旧备份保留复习状态检查点。跳过状态以服务器最后接受的修改为准；取消跳过也保存，避免旧设备恢复已取消状态。
- 每账号同步文本上限 50 MiB，按每条记录的 key 和 jsonb 文本累计；单条记录上限 16 KiB。PostgreSQL 计算 jsonb 文本时会在 `,` 和 `:` 后加空格，网页按同样方法计算，不会上传服务器必然拒收的记录。达到账号容量后，新增记录留在本机队列，不自动收费、不自动删除历史。备份仍为原进度 JSON。
- 网页不再提供 Anki 导入，也不再显示旧版本导入的卡组；如需使用自己的卡组，请联系作者。
- 目前每日新句上限按各设备本地日期计算；离线多端练习可能超过设定数量，同步会保留实际发生的学习记录。
- Supabase 控制台是当前容量监控入口。免费额度达到 80% 时暂停扩大用户规模，评估备份和扩容；不要把免费额度描述为无限保存。

## 4. 数据与权限

专用表启用 RLS，并撤销匿名、普通登录角色直接访问表的权限。公开 RPC 只授权 authenticated，所有读写从 `auth.uid()` 获取归属，不接受客户端提供的 user_id。函数固定空 search_path。删除账号前界面要求重新输入密码；服务器也要求 10 分钟内的密码登录（JWT `amr`），仅凭复制的访问令牌无法删除账号。服务器删除当前账号及级联同步数据。

云端记录包括邮箱（Auth）、评分、历史、复习状态和跳过记录。不上传卡组、设置或原始按键序列。退出后本地账号缓存保留并隔离；在公共设备上请清除网站数据。

生产前：备份 Supabase 的 Auth 和 public 数据，并实际恢复到隔离测试项目验证。凭据与备份不提交到 Git，也不上传公开 CI artifacts。用户可以随时导出原 JSON 进度备份。

## 5. 上线验收

用两个测试账号、两个浏览器测试：注册、验证、登录、重设密码；双设备离线练习后合并；同一记录重复提交；超过云端限制的记录不阻塞其他记录；取消跳过；设置只留在本机；游客合并；退出切换账号；删除账号。账号 A 不能读写 B 的行，匿名调用 RPC 被拒绝。确认这些实测通过后再开放公众注册。

`npm test` 包含 IndexedDB 原子写入与升级、同步重放、逐条结果与隔离测试，以及 PGlite 执行真实迁移 SQL 的权限、幂等、容量计数和 jsonb 大小一致性测试。PGlite 验证不能代替实际 Supabase Auth 和邮箱测试。
